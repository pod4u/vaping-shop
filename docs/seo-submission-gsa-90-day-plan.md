# แผน Submission และ GSA ระยะ 90 วันสำหรับ Pod4U

วันที่จัดทำ: 13 กันยายน 2026

## เป้าหมาย

เพิ่มโอกาสให้ Google ค้นพบและจัดอันดับหน้าที่มีประโยชน์ พร้อมสร้างการกล่าวถึง Pod4U จากแหล่งภายนอกที่เกี่ยวข้องจริง โดยไม่ใช้การส่งลิงก์จำนวนมากเป็นตัวชี้วัดความสำเร็จ

แผนนี้ให้ GSA Search Engine Ranker เป็นเครื่องมือช่วยจัดการงานที่ได้รับอนุญาตแล้วเท่านั้น ไม่ใช้ GSA ค้นหาเว็บแบบสุ่ม สร้างบัญชีปลอม โพสต์คอมเมนต์ หรือสร้างลิงก์จำนวนมากเข้าหน้าหลักของร้าน

## แยกงานออกเป็น 3 ช่องทาง

| ช่องทาง | วิธีทำ | เครื่องมือหลัก | เป้าหมาย |
| --- | --- | --- | --- |
| Search submission | ส่ง sitemap และตรวจ URL สำคัญ | Google Search Console | ให้ Google ค้นพบและประมวลผลหน้าจริง |
| Owned/approved submission | แก้ URL ในโปรไฟล์ร้าน ไดเรกทอรีที่มีคนใช้จริง และหน้าคู่ค้าที่ร้านมีสิทธิ์ | ทำด้วยคนก่อน | สร้างตัวตนและ referral traffic |
| Editorial mentions | ให้ข้อมูลที่เป็นประโยชน์แก่ผู้เผยแพร่หรือคู่ค้าที่เกี่ยวข้อง | Outreach รายแหล่ง | ได้การกล่าวถึงที่เกิดจากเนื้อหาและความสัมพันธ์จริง |

GSA ใช้ได้เฉพาะช่องทางที่สอง เมื่อมีรายชื่อ URL ที่ตรวจและอนุมัติล่วงหน้าแล้ว และการใช้งานไม่ขัดเงื่อนไขของเว็บไซต์ปลายทาง

## เงื่อนไขก่อนเริ่ม

- Sitemap ใน Search Console ต้องอ่านได้และไม่มีข้อผิดพลาดสำคัญ
- หน้าที่จะประชาสัมพันธ์ต้องตอบคำถามได้จริง มี canonical ถูกต้อง และไม่มี `noindex`
- มีรายการแหล่งเป้าหมาย พร้อมเหตุผลว่าเกี่ยวข้องกับ Pod4U อย่างไร
- ยืนยันสิทธิ์ก่อนสร้างบัญชีหรือส่งข้อมูลทุกครั้ง
- ตรวจข้อกฎหมายไทยและนโยบายของแพลตฟอร์มสำหรับสินค้าควบคุมก่อนเผยแพร่หรือซื้อโฆษณา
- ห้ามใส่เว็บลง GSA จนกว่าจะผ่านตารางคัดกรองและมีสถานะ `อนุมัติ`

## การตั้งค่า GSA สำหรับการทดลอง

ชื่อโปรเจกต์: `Pod4U - Approved Submission Only`

| การตั้งค่า | ค่าเริ่มต้น |
| --- | --- |
| Target source | นำเข้าเฉพาะ whitelist ที่อนุมัติ ห้ามค้นหาเป้าหมายอัตโนมัติ |
| Threads | 1 |
| Platform/engine | เปิดเฉพาะประเภทและเว็บไซต์ที่ตรวจข้อกำหนดแล้ว |
| Content spinning | ปิด |
| Random account/profile creation | ปิด |
| Forum/comment/wiki submission | ปิด เว้นแต่เป็นบัญชีจริงของร้านและเว็บไซต์อนุญาตอย่างชัดเจน |
| Anchor text | ใช้ข้อความตามบริบท ไม่ตั้งสูตรเพื่อปั่นสัดส่วนคีย์เวิร์ด |
| CAPTCHA | ทำด้วยคนในช่วงทดลอง |
| Proxy | ปิดในช่วงทดลอง |
| Verification | เปิดตรวจว่าหน้าเผยแพร่จริงและ URL ยังทำงาน |
| Daily limit | ไม่กำหนดจากจำนวนที่อยากได้ แต่จำกัดตามรายชื่อที่อนุมัติจริง |

ให้แยกข้อมูลล็อกอินของแต่ละเว็บไซต์ เก็บในระบบจัดการรหัสผ่าน และส่งออกประวัติ verified URLs หลังจบแต่ละรอบ ห้ามนำอีเมลลูกค้า บัญชีบุคคลอื่น หรือข้อมูลที่ไม่ได้รับอนุญาตมาใช้

## แผน 90 วัน

### ระยะที่ 1 — วันที่ 1–14: วางฐานและทดลองแบบควบคุม

1. บันทึก baseline จาก Search Console: clicks, impressions, CTR, average position และ query-to-page ของกลุ่ม MARBO
2. ตรวจ sitemap, canonical, indexability และ internal links ของหน้าเป้าหมายทั้ง 5 หน้า
3. ทำบัญชีแหล่งภายนอกที่ร้านเป็นเจ้าของอยู่แล้ว เช่น โปรไฟล์ธุรกิจหรือช่องทางสังคมที่ใช้งานจริง
4. ทำรายชื่อคู่ค้า ผู้จัดจำหน่าย หรือผู้เผยแพร่ที่มีความสัมพันธ์และผู้อ่านจริง
5. ให้คะแนนแต่ละแหล่ง แล้วเลือกทดลองไม่เกิน 3–5 แหล่ง
6. ส่งด้วยคนก่อนหนึ่งรอบ เพื่อเรียนรู้แบบฟอร์ม กฎ และผลลัพธ์จริง
7. ตั้ง GSA ตามค่าด้านบน แต่ยังไม่เปิดการค้นหาเป้าหมายอัตโนมัติ

ผลลัพธ์ที่ต้องได้: whitelist ชุดแรก, baseline, ผู้รับผิดชอบ และประวัติการส่งที่ตรวจย้อนกลับได้

### ระยะที่ 2 — วันที่ 15–30: ส่งเฉพาะแหล่งที่อนุมัติ

1. แก้ลิงก์เว็บไซต์ในโปรไฟล์ที่ Pod4U เป็นเจ้าของให้ถูกต้อง
2. ส่งข้อมูลไปยังแหล่งที่ผ่านอนุมัติทีละรายการ รวมเดือนแรกไม่เกิน 5–10 รายการ
3. ใช้ GSA เฉพาะงานฟอร์มซ้ำที่เว็บไซต์อนุญาตและทดสอบด้วยคนแล้ว
4. ตรวจทุกลิงก์หลังเผยแพร่: หน้าเปิดได้ เนื้อหาไม่ผิด บริบทตรง และไม่สร้างคำกล่าวอ้างเกินจริง
5. หากเป็น placement ที่จ่ายเงินหรือได้รับสิ่งตอบแทน ต้องระบุลิงก์เป็น `sponsored` หรือ `nofollow` ตามความเหมาะสม
6. บันทึก referral traffic และ query-to-page ทุกสัปดาห์ แต่ไม่ตัดสินอันดับจากข้อมูลเพียงไม่กี่ impressions

ผลลัพธ์ที่ต้องได้: การกล่าวถึงหรือลิงก์ที่เกี่ยวข้องจริง 1–3 แหล่ง โดยไม่มีสแปมหรือคำเตือนจากแพลตฟอร์ม

### ระยะที่ 3 — วันที่ 31–60: คัดผู้ชนะ ไม่ขยายทุกช่องทาง

1. แยกผลเป็น accepted, rejected, pending และ removed
2. ขยายเฉพาะประเภทที่มีผู้อ่านจริง ส่ง referral traffic หรือสร้างความสัมพันธ์ที่ใช้ต่อได้
3. หยุด directory หรือแหล่งที่ไม่มีผู้อ่าน มีหน้าเต็มไปด้วยลิงก์ หรือขอให้แลกลิงก์จำนวนมาก
4. ตรวจ branded impressions ของ `MARBO`, `มาโบ`, `มาร์โบ` และ impressions ของหน้าแบรนด์/รุ่น
5. สร้าง outreach asset จากข้อมูลจริง 1 ชิ้น เช่น ตารางเปรียบเทียบรุ่นหรือข้อมูลรสที่อัปเดตจากแคตตาล็อก เพื่อให้ผู้เผยแพร่มีเหตุผลอ้างถึง
6. พิจารณา CAPTCHA/Proxy เฉพาะเมื่อผ่านเกณฑ์ด้านล่าง ไม่ซื้อไว้ก่อน

ผลลัพธ์ที่ต้องได้: รู้ว่าแหล่งประเภทใดมีคุณค่า และตัดช่องทางที่สร้างแต่จำนวนลิงก์ออก

### ระยะที่ 4 — วันที่ 61–90: ทำเป็นระบบประจำ

1. กำหนดรอบ review รายสัปดาห์ 30–60 นาที และรายเดือน 2 ชั่วโมง
2. ตรวจ verified links ว่ายังอยู่และพาไปหน้าที่เหมาะสม
3. ตรวจ Manual Actions, Security Issues, sitemap และ indexing ใน Search Console
4. เทียบผลกับ baseline โดยใช้แนวโน้ม 28 วัน ไม่ใช้การค้นหาเองเป็นหลักฐานอันดับ
5. เพิ่มแหล่งใหม่เฉพาะเมื่อผ่านเกณฑ์คุณภาพเท่าเดิม
6. สรุปว่าจะต่อยอดหน้าใดจาก query จริง และปรับ content/internal links ก่อนหา external links เพิ่ม

ผลลัพธ์ที่ต้องได้: workflow ที่ทำซ้ำได้ มีข้อมูลตัดสินใจ และไม่มีแรงกดดันให้เพิ่มจำนวนลิงก์อย่างไร้คุณภาพ

## เมื่อไรควรซื้อ CAPTCHA

ช่วงเริ่มต้นให้ใช้ manual CAPTCHA เพราะจำนวนแหล่งที่อนุมัติควรน้อย การเจอ CAPTCHA ยังเป็นสัญญาณให้ตรวจว่าการส่งอัตโนมัติได้รับอนุญาตหรือไม่

พิจารณาบริการ CAPTCHA แบบเสียเงินเมื่อครบทุกข้อ:

- มี approved queue มากกว่า 20 รายการต่อเดือน
- การกรอกด้วยคนใช้เวลามากกว่า 2 ชั่วโมงต่อเดือน
- เว็บไซต์ปลายทางอนุญาตการส่งข้อมูลลักษณะนั้น
- อัตราการยอมรับจากการทดลองด้วยคนอยู่ในระดับดี
- ตั้งงบทดลองและเพดานค่าใช้จ่ายได้ เช่น 300–500 บาทต่อเดือน

หยุดทันทีเมื่อ CAPTCHA เพิ่มผิดปกติ มีการ block หรือผลสำเร็จต่ำ เพราะการเพิ่มงบเพื่อฝ่ากลไกป้องกันไม่ใช่เป้าหมายของแผน

## เมื่อไรควรใช้ Proxy

เดือนแรกให้ปิด Proxy และใช้การเชื่อมต่อปกติ Proxy ไม่ได้ทำให้ลิงก์มีคุณภาพขึ้น

ใช้ได้เมื่อมีเหตุผลด้านระบบที่ชัดเจน เช่น GSA ทำงานบน Windows VPS ที่ต้องมี IP คงที่ หรือบริการปลายทางกำหนดการเชื่อมต่อที่ได้รับอนุญาต โดยมีเงื่อนไขดังนี้:

- ใช้ private proxy หรือ IP คงที่ที่เชื่อถือได้ ไม่ใช้ free public proxy
- ไม่หมุน IP เพื่อหลบ rate limit, CAPTCHA, การแบน หรือข้อจำกัดของเว็บไซต์
- ใช้ identity และตำแหน่งที่สอดคล้องกับธุรกิจจริง
- ซื้อหลังพิสูจน์แล้วว่าจำเป็นเท่านั้น และทบทวนค่าใช้จ่ายทุกเดือน

หากไม่มีเหตุผลด้านระบบ ให้คง Proxy เป็น `ปิด` ต่อไป

## ตารางคัดกรองก่อนอนุมัติ

ให้คะแนน 0–2 ในแต่ละหัวข้อ ต้องได้อย่างน้อย 8/10 และไม่มี red flag จึงอนุมัติ

| เกณฑ์ | 0 | 1 | 2 |
| --- | --- | --- | --- |
| ความเกี่ยวข้อง | ไม่เกี่ยวข้อง | เกี่ยวข้องกว้าง ๆ | ตรงสินค้า/ผู้ชม |
| ผู้อ่านจริง | ไม่พบหลักฐาน | ยังไม่ชัด | มีชุมชนหรือผู้ชมจริง |
| สิทธิ์ในการส่ง | ไม่อนุญาต | ต้องสอบถาม | เป็นบัญชีร้าน/ได้รับอนุญาต |
| คุณภาพหน้า | หน้าเต็มไปด้วยลิงก์ | คุณภาพปานกลาง | มีเนื้อหาและการดูแลจริง |
| ประโยชน์ต่อผู้อ่าน | มีไว้ใส่ลิงก์ | มีประโยชน์บางส่วน | ช่วยค้นข้อมูล/ตัดสินใจจริง |

Red flags: รับประกันอันดับ, ขาย dofollow เป็นแพ็ก, สร้างลิงก์หลายพันรายการ, บังคับ anchor text, ขอแลกลิงก์เป็นเครือข่าย, หน้าไม่มีผู้อ่าน, หรือไม่ให้แก้/ลบข้อมูลภายหลัง

## Tracker ที่ต้องบันทึก

เริ่มบันทึกสถานะจริงใน [Submission Tracker](./seo-submission-tracker.md) โดยรายการที่ยังไม่ส่งต้องใช้สถานะ `รอตรวจ` หรือ `พักไว้` เท่านั้น

| ฟิลด์ | รายละเอียด |
| --- | --- |
| Source URL | URL เว็บไซต์หรือหน้าแบบฟอร์ม |
| Owner/permission | ใครเป็นเจ้าของและมีสิทธิ์ส่งอย่างไร |
| Category | owned profile, partner, directory, editorial |
| Score/status | คะแนนคัดกรองและสถานะอนุมัติ |
| Target URL | หน้า Pod4U ที่ตรงกับบริบท |
| Context/anchor | ข้อความรอบลิงก์ที่ใช้จริง |
| Submitted date | วันที่ส่ง |
| Result | pending, accepted, rejected, removed |
| Live URL | URL ที่เผยแพร่แล้ว |
| Link attribute | follow, nofollow, sponsored, unknown |
| Referral/conversion | การเข้าชมและผลลัพธ์ที่วัดได้ |
| Removal access | วิธีแก้หรือลบเมื่อข้อมูลผิด |
| Notes | ข้อผิดพลาด เงื่อนไข และขั้นต่อไป |

## ตัวชี้วัด

### ตรวจทุกสัปดาห์

- จำนวนแหล่งที่ตรวจและจำนวนที่อนุมัติ
- จำนวนที่ส่ง สำเร็จ รอ และถูกปฏิเสธ
- ลิงก์ที่ยังเปิดได้และหน้าเป้าหมายถูกต้อง
- referral visits และ conversion ที่วัดได้
- Search Console query-to-page ของกลุ่ม MARBO

### ตรวจทุกเดือน

- จำนวน referring sources ที่เกี่ยวข้องจริง ไม่ใช่จำนวน backlinks รวม
- accepted rate ของแต่ละประเภทแหล่ง
- branded impressions/clicks ของ MARBO, มาโบ และมาร์โบ
- impressions/clicks ของหน้าแบรนด์ 9K และ 15K
- Manual Actions, Security Issues และ indexing anomalies
- เวลาคนและค่าใช้จ่ายต่อ placement ที่มีคุณภาพ

ไม่ใช้ Domain Authority, จำนวนลิงก์รวม หรืออันดับจากการค้นหาด้วยเครื่องตัวเองเป็น KPI หลัก

## เงื่อนไขหยุดแคมเปญ

หยุด GSA และตรวจด้วยคนทันทีเมื่อเกิดข้อใดข้อหนึ่ง:

- ได้ HTTP 403/429, CAPTCHA เพิ่มขึ้น หรือบัญชีถูกจำกัดซ้ำ
- มีข้อความร้องเรียน คำเตือนจากแพลตฟอร์ม หรือคำเตือนใน Search Console
- แหล่งเผยแพร่เนื้อหาผิดบริบท สร้างหน้าซ้ำ หรือเปลี่ยนข้อความโดยไม่ได้อนุมัติ
- verified rate หรือ accepted rate ต่ำกว่า 60% ในชุดทดลอง
- พบ referring domains ที่ไม่เกี่ยวข้องเพิ่มขึ้นผิดปกติ
- ทีมอธิบายไม่ได้ว่าลิงก์แต่ละรายการช่วยผู้อ่านอย่างไร

เมื่อหยุด ให้เก็บ log ระบุชุด URL ที่ได้รับผลกระทบ ปิดแคมเปญ และแก้หรือลบ placement ที่ควบคุมได้ก่อนเริ่มใหม่

## แผนเดือนที่ 4–12

- ทำ content และ internal links ตามข้อมูล Search Console เป็นฐานก่อน outreach ทุกไตรมาส
- ตั้งเป้าคุณภาพแบบกว้าง ๆ 3–8 การกล่าวถึงหรือแหล่งอ้างอิงจริงต่อไตรมาส ไม่รับประกันจำนวนและไม่เร่งเมื่อไม่มีโอกาสที่เหมาะสม
- ตรวจ owned profiles และลิงก์คู่ค้าทุกไตรมาส
- สร้าง asset ที่อ้างอิงได้จากข้อมูลจริงอย่างน้อยไตรมาสละ 1 ชิ้น
- ประเมิน GSA ทุกไตรมาส หากงานที่อนุมัติมีน้อยกว่าต้นทุนการดูแล ให้กลับไปทำด้วยคนทั้งหมด
- ทบทวนกฎหมาย นโยบายแพลตฟอร์ม และ Google spam policies ก่อนเริ่มรอบใหม่

## งานที่ควรทำใน 7 วันถัดไป

1. สร้าง tracker ตามฟิลด์ข้างต้น
2. บันทึก Search Console baseline ช่วง 28 วัน
3. รวบรวม owned profiles และคู่ค้าที่มีความสัมพันธ์จริง 10 รายชื่อ
4. ให้คะแนนทุกแหล่ง เลือก approved trial ไม่เกิน 3–5 แหล่ง
5. ทดลองส่งด้วยคนหนึ่งรอบก่อนตั้ง GSA
6. ตั้งโปรเจกต์ GSA แบบ whitelist-only โดยยังปิด CAPTCHA service และ Proxy
7. Review ผลหลัง 7 วัน แล้วจึงตัดสินใจว่าจะทำซ้ำ ออกจากช่องทาง หรือขยายอย่างจำกัด
